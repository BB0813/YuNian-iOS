## 1. 为什么重写（先说清楚，避免重蹈）

旧视觉层（`Views/` 3967 行 + `Theme/` 1538 行 = 5505 行）已被**整体废弃**。
废弃原因**不是"bug 多"**，而是**指导方针错了**：

> 旧方针：**逐条复刻 Android**。每个数值都在注释里标着 Kotlin 行号。

这条方针在结构上保证了三种必然的坏结果，且**每一种都真实发生了**：

| 必然结果 | 实际发生的例子 |
|---|---|
| 把 Android 的**权宜之计**当成规格抄过来 | 一个叫"液态玻璃"的组件，逐条复刻 Android 手搓的假折射（`lens()` + 隐藏捕获层），而 **iOS 26 有原生 `.glassEffect`** |
| 把 Android 的**层级机制**硬搬到没有对应物的平台 | `GlassPageScaffold` 复刻 Kotlin 的 `layerBackdrop`，注释自己写着"在 SwiftUI 无对应物" |
| 逐字段转写产生**静默错位** | `textTertiary: Palette.darkElevated` —— 把背景色当成了文字色，实测对比度 **1.41:1**（正文要求 ≥4.5） |

**结论：只要"与 Android 对齐"还是验收标准，重构多少次都会长回同一批问题。**

## 2. 方针（本文件最重要的一节）

### 2.1 一句话

> **原生 iOS 优先。凡是 iOS 26 有原生 API 的，一律用原生；不自绘。**

### 2.2 硬规则

1. **能原生就原生。** 玻璃 → `.glassEffect`；按钮 → `.buttonStyle(.glass)` /
   `.glassProminent`；筛选 → `Picker(.segmented)`；工具栏 → `.toolbar`；
   列表 → `List` + `.listStyle(.insetGrouped)`；弹层 → `.sheet` / `.alert`。
2. **禁止手搓玻璃。** 任何用「半透明色块 + 描边 + 模糊」去"逼近"玻璃的实现都不允许存在。
3. **禁止在玻璃后面放不透明背景。** 玻璃采样的是背后的像素；背后若是纯色，
   玻璃必然渲染成死灰。这是旧代码最普遍的一个 bug（三个 tab 页 + 二级页骨架全都中招）。
4. **`.glassEffect()` 必须在 `frame` / `font` / `padding` 之后调用。**
5. **`.interactive()` 只给可交互元素**，不是所有玻璃都要响应触摸。
6. **不再以 Android 为观感基准。** 需要跨端一致时，一致性由**产品语义**保证
   （同样的信息、同样的流程），**不由像素保证**。
7. **一处玻璃 = 一处控制。** 玻璃是稀缺资源；满屏玻璃等于没有玻璃。

### 2.3 与 Android 的关系

保留：数据模型、业务流程、文案语义、功能覆盖。
放弃：材质实现、圆角数值、间距数值、"看起来一样"这个目标。

## 3. 三层材质（整套 UI 的骨架）

```
┌─────────────────────────────────────────────┐
│  控制层   .glassEffect                       │  悬浮在内容之上
│  底栏 / 顶栏 / 主操作按钮                      │  需要透出下面的内容
├─────────────────────────────────────────────┤
│  内容层   surface（实心色调面）                │  安静、可读
│  卡片 / 分组 / 列表行 / 表单                   │  不需要透出任何东西
├─────────────────────────────────────────────┤
│  画布     Canvas（渐变 + 品牌辉光）             │  垫在所有内容之下
│                                               │  它存在的唯一理由是"给玻璃可采样的东西"
└─────────────────────────────────────────────┘
```

### 3.1 画布细则（第 220 轮「暖夜」补充）

画布 = **黄昏渐变 + 双光源 + 极轻颗粒**，三件事都必须有：

| 元素 | 规格 | 为什么 |
|---|---|---|
| 黄昏渐变 | `backgroundElevated → background`，上暖下暗 | 旧实现两色只差 **0.003 亮度**，肉眼是一块死黑 —— 画布等于不存在 |
| 品牌光源 | `canvasGlow` 右上，径向 30% → 10% → clear | 上文"给玻璃可采样的东西"的前提；没有它，控制层玻璃渲染成死灰 |
| 暖色光源 | `canvasGlowWarm` 左下，同上但更小 | 「暖夜」的体积感来源；只靠一个冷色光源会显得平 |
| 颗粒 | 程序生成的固定种子点阵，不透明度 **0.05**（浅色 0.035） | 破掉数字平面的塑料感 |

**硬规则**
- 颗粒**必须固定种子**：每帧重新随机的颗粒在 OLED 上像故障噪点，比不加更糟。
- 画布**永不承载信息** —— 任何"只靠画布深浅传达状态"的实现都是 bug。
- `Reduce Transparency` → 去掉双光源与颗粒，只留纯色渐变；
  `Reduce Motion` → 光源静止（不做呼吸）。
- 颗粒与光源都**不得**超过各自的不透明度上限（改了要重新量对比度）。

### 判定表 —— 新组件该用哪层？

| 问自己 | 是 → | 否 ↓ |
|---|---|---|
| 它悬浮在内容**之上**、且需要透出下面吗？ | **控制层（玻璃）** | 继续 |
| 它是用户要**读**或**填**的东西吗？ | **内容层（面）** | 继续 |
| 它是铺满整屏的底吗？ | **画布** | 用色调面兜底 |

**典型误判**：把内容卡片做成玻璃。旧代码在 **8 个**卡片上这么做了。
后果是每块都是玻璃 ⇒ 没有一块读起来像玻璃，外加 8+ 个独立模糊同时合成，
以及"内容"与"导航"变成同一材质、眼睛分不出哪里能点。

## 4. 颜色

### 4.1 决策一：主色从「蓝」改成「紫罗兰」

旧代码的 `primary = #4A9EFF`（冷蓝），压在暖紫底（`#16131F`）上 —— **两个色相在低透明度下互相污染，观感就是"脏"**。

而这个蓝色的来历是一次**命名事故**：Kotlin 里它叫 `PinkPrimary`，是个粉色常量，
值却写成了蓝。旧代码的注释已经如实记录了这件事：

> `PinkPrimary = 0xFF4A9EFF` **是蓝色，不是粉色**

品牌真实的身份色一直是**紫罗兰/薰衣草**（`pastelLilac #CCA8E9` / `pastelLavender #C3BEF0`），
App 名"予念"的气质也在这一族。

**决策**：`primary` = 紫罗兰；蓝降级为 `info` 语义色，不再承担主色。

### 4.2 暗色 ramp（默认档 · 第 220 轮「暖夜」修订）

> **为什么改**：上一版为了避免"满屏紫"，把内容面去饱和成**中性灰**（饱和 18%）。
> 结果整屏是"深灰底 + 灰卡片"—— 干净，但实测观感反馈是
> **「单调 / 无聊 / 没有使用欲望」**。修订方向：内容面**往暖侧偏**
> （色相 ~330 玫瑰紫，而不是 255 蓝紫），饱和度小幅回到 ~14%。

| `canvasTop` | `#1E1930` | 画布上端（暖，可被看见） |
| `canvasBottom` | `#14111D` | 画布下端 |
| `canvasGlow` | `#7C5CE6` | 品牌辉光（右上光源） |
| `canvasGlowWarm` | `#E08A5F` | 暖色第二光源（左下） |

### 4.6 两个强调色的分工（第 220 轮新增，**硬约定**）

设计系统原本只留一个强调色。实测证明那会**偏冷**（紫罗兰画布 + 灰面 + 紫罗兰强调 = 全屏无暖色）。
现在有两个，但**职责不许重叠**：

| | `accent`（紫罗兰） | `warm`（蜜琥珀） |
|---|---|---|
| 承担 | **品牌与交互** | **情感与注意** |
| 具体用于 | 选中态、主操作、可点文字、链接 | 未读标记、亲密度、头像光晕、需要被看见的提醒 |
| 禁止 | 表达"注意/未读" | 做按钮主色、做选中态 |

**两者不得同时出现在同一个控件上。** 需要"选中且有未读"时，用 `accent` 表达选中、
把未读交给**图形**（圆点）或字重，不要双色叠加。

### 4.5 对比度门槛（**硬性，验收时实测**）

| 内容 | 最低 |
|---|---|
| 正文、占位符、可点文字 | **4.5:1** |
| 大字号（≥18pt 或粗体 ≥14pt） | 3:1 |
| 图标（承载语义时） | 3:1 |

> **注意**：`textTertiary` 是**下限**，不是"再淡一点更好看"的起点。
> 旧代码的 1.41:1 就是这么来的。任何"为了优雅而调淡"的改动都要先过一遍对比度。
> **占位符文字同样要 4.5:1**，不能因为它"只是提示"就放过。

## 5. 字体

**只用系统字体**（San Francisco / 苹方）。不引入自定义字体 ——
自定义字体在中文下会破坏字重与字距的系统级调优，且不随动态字体缩放。

| 角色 | 字号 / 字重 | 用途 |
|---|---|---|
| **`display.hero`** | **34 / bold，字距 −0.6** | **门面页大标题**（会话列表 / 我 / 通讯录） |
| `display.heroSmall` | 28 / bold | 次级门面 / 空态标题 |
| `display.section` | 20 / semibold，字距 −0.2 | 区块标题 |
| `screenTitle` | 28 / bold | 一级页大标题（系统 `.largeTitle`） |
| `navTitle` | 17 / semibold | 导航栏标题（**二级页仍用它**） |
| `rowTitle` | 17 / regular | 列表行主文字 |
| `rowSubtitle` | 15 / regular | 列表行副文字 |
| `body` | 17 / regular | 正文 |
| `caption` | 13 / regular | 元信息 |
| `tabLabel` | 10 / medium | 标签栏文字（系统量级） |

**规则**
- 优先用语义字号（`.body` / `.headline` / `.caption`）以获得动态字体支持；
  确需精确控制时才用 `.system(size:)`（**显示级字号是唯一允许写死的一档** ——
  它承担的是版式角色，且门面页本身不放正文）。
- 一行正文 **≤ 42 个中文字符**。
- 不用`全部大写 + 宽字距`的小标签（"eyebrow"）作为每个区块的装饰。
- **大字号必须收紧字距**：34pt 不加 −0.6 的字距，中文会散开、显得松散。
- **门面页与二级页必须有不同的标题量级**：门面页用 `display.hero` 自绘页头
  （系统导航栏 17pt 撑不起门面），二级页继续用系统导航栏 `.inline`。
  两者混用会出现"每页标题一样大"的平铺感。

## 6. 间距与圆角

### 6.1 间距：4pt 基网

| token | 值 | 用途 |
|---|---|---|
| `xs` | 4 | 图标与紧邻文字 |
| `sm` | 8 | 同组元素 |
| `md` | 12 | 行内边距 |
| `lg` | 16 | **页面左右边距** |
| `xl` | 20 | 卡片内边距 |
| `xxl` | 28 | 区块之间 |
| `section` | 40 | 大区块之间 |

**节奏**：不要所有间距都是 16。相邻区块之间应比组内元素更大，
形成"这是新的一组"的视觉暗示。

### 6.2 圆角阶梯

| token | 值 | 用途 |
|---|---|---|
| `chip` | 8 | 标签、小控件 |
| `field` | 10 | 输入框 |
| `row` | 12 | 列表行 |
| `card` | 16 | **卡片上限** |
| `sheet` | 20 | 弹层、抽屉 |
| `continuous` | `.continuous` 样式 | **所有圆角必须用 `.continuous`**，不用默认的 circular |

> **卡片圆角上限 16。** 24 / 28 / 32 的卡片圆角是"看起来廉价"最典型的来源之一。
> 胶囊（`.infinity`）只用于 chip、开关、标签，**不用于列表行和卡片**。

### 6.3 同心圆角（Apple HIG 26 代起的原则）

嵌套的两层，内层半径 = 外层半径 − 内边距。

```
内径 = max(外径 - inset, 6)
```

违反同心性会让界面"发涩"，且很难指出具体哪里不对 —— 所以必须写成公式、不能靠眼调。

### 6.4 高度（第 220 轮新增）

旧实现**几乎没有任何高度线索**：画布、内容面、次级面挤在一条很窄的亮度带上，
层次读不出来，整屏像"一整块"。现在给两档投影：

| token | 规格 | 用途 |
|---|---|---|
| `Elevation.card` | `black 28% / r14 / y6` | 内容面：只把面从画布上"抬起来" |
| `Elevation.raised` | `black 36% / r22 / y10` | 悬浮 / 强调块（弹层、主卡） |
| `Elevation.glow(color)` | `color 35% / r12 / y2` | 头像/未读的**暖色光晕**（不是黑边） |

**硬规则**
- **描边与投影互斥**（反模式 7）：用了 `ynElevation` 就不要再加 1px 描边。
- 需要更强分层时**换面色**（`surface` → `surfaceElevated`），不是叠第二层阴影。
- 一屏最多 **2 处** `Elevation.raised`；`Elevation.card` 不限制但**不应出现在列表行上**
  （列表行靠分隔线与留白分层，不靠卡片 —— 反模式"卡片套卡片"）。

## 7. 动效

| 场景 | 曲线 | 时长 |
|---|---|---|
| 状态切换（选中、展开） | `Motion.spring` = `spring(response: 0.34, dampingFraction: 0.86)` | — |
| 元素进出 | `Motion.quick` = `.easeOut` | 200ms |
| 玻璃形变（morph） | 系统默认（`glassEffectID` + `withAnimation`） | — |

**规则**
- 用指数衰减的 ease-out，**不用回弹/弹性**。
- 不动画布局属性（除非确有必要）。
- **尊重"减弱动态效果"**：`@Environment(\.accessibilityReduceMotion)` 为真时改为交叉淡入。
- 列表项逐个入场是合理的；**"每个区块都套同一个入场动画"是反模式**。

### 7.1 入场动画的**上限**（第 220 轮补充）

"逐个入场"很容易失控成"整页都在动"。因此把它写成可计算的约定：

| 约束 | 值 | 原因 |
|---|---|---|
| 步进 | `Motion.entryDelay(index, step:)` 默认 0.03s | 再密就看不出错峰 |
| 上限 | **0.24s**（`cap` 参数写死） | 超过 1/4 秒的等待会让人觉得"卡" |
| 作用范围 | **只有首屏第一组**，且只跑一次 | 滚动回来重放 = 每次滚都闪一遍 |
| `reduceMotion` | 跳过（直接终态） | 无障碍硬要求 |
| 位移量 | ≤ 6pt | 大位移动画在这个 App 的节奏里太重 |

### 8.1 第 220 轮新增的原语（`Theme/YNPrimitives.swift`）

| 原语 | 材质层 | 解决什么 |
|---|---|---|
| `YNPageHeader` | 无材质（文字层） | 门面页**没有大标题**（全屏最大的字曾是 17pt 导航栏标题）；右侧可挂轻量计数 |

> ⚠️ 这四个原语是**唯一**允许自绘"面/页头/空态"的地方。新页面直接复用，

## 9. 屏幕清单与验收

每一屏都要过这张表才算完成：

- [ ] 玻璃只用在控制层（数一遍：这一屏有几处 `.glassEffect`？**应为 0–2 处**）

## 10. 反模式（明令禁止）

1. **手搓玻璃** —— 半透明色块 + 描边 + 模糊去逼近玻璃。
2. **玻璃叠玻璃** —— 会按 `GlassEffectContainer` 的 `spacing` 融成一团，选中态消失。
3. **在不透明背景上放玻璃** —— 玻璃必然变死灰。
4. **把内容卡片做成玻璃** —— 玻璃是控制层的材质。
5. **同屏两个同款玻璃胶囊** —— 旧代码在首页犯了：顶部分段筛选和底部导航用了同一个组件。
6. **同屏两处导航供具** —— 筛选不是导航，别用导航的控件做筛选。
7. **1px 描边 + 大范围软投影同时出现在一个元素上**（"幽灵卡片"）—— 二者只留一个。
8. **卡片圆角 ≥ 24**、**列表行用胶囊**。
9. **渐变文字**（`background-clip: text` 的等价物）。
10. **侧边色条**（左侧 4pt 彩色竖条）作为强调。
11. **每个区块都套"小号大写宽字距"标签**。
12. **空态是无出路的文案**（"去 XX 找…" 却不给入口）。
13. **给用户看开发术语**（旧代码里出现过"播种默认伴侣"）。
14. **为观感去对齐 Android**。
